# 账号、订单与课程权限运行说明

## 当前上线边界

正式网址：https://wuxufinance.github.io/wuxufinance/ 。学习中心入口为`learn/#/account`，后台为`admin.html`。复用现有GitHub Pages、Supabase Auth、Postgres及`finance-api`，没有新建收费服务或另一个网站。

现有43讲保持登录免费、原文、原版本、稳定编号与设备审批。没有设置正式售价、真实支付渠道或内部授权名单。公开首页、目录、课程介绍、专题与工具继续提供完整静态HTML及原有SEO配置。新增公开正文/试听由API按公开配置返回，显示在正式站点原有静态课程介绍下方；只在管理员逐讲明确配置后公开，不自动公开现有受限课程。

邮件服务尚未配置，`account_delivery.email_ready`保持`false`。注册和密码找回表单明确暂未开放；不能把隔离测试或Supabase默认测试邮件当作真实投递验收。已有账号、内部授权、后台商品订单与人工收款记录可用。在线付款固定关闭，不展示假支付按钮。

## 真实认证与会话

邮箱注册、邮箱验证、密码登录、退出和找回密码通过Supabase Auth。密码不进入应用数据库或日志；服务端凭据仅为Edge环境变量。浏览器保存的随机设备凭据和Auth会话用于正常身份流程，不能直接决定管理员、授权或支付状态。

新用户只有在Supabase邮箱已验证、Auth会话有效后，才由后端建立`student`普通身份，设备上限默认2。用户可编辑的Auth metadata仅用于显示名称，不读取其中的角色、账号状态或授权。现有账号的角色、状态和设备审批不改动。管理员创建的学员保留手工设备审批。

验证/找回链接采用PKCE，验证码也可在验证页输入。邮箱模板不能改成前端直接接收未经交换的token。登录前课程路径保存在同一浏览器会话中，完成登录后只允许返回站内学习路径，拒绝外站回跳和后台地址注入。

## SMTP与注册开放

由项目所有者在Supabase控制台安全填写SMTP host、port、sender、user和password，不在聊天、GitHub或前端填写密钥。

1. Authentication的邮件投递配置启用可靠的自定义SMTP，设置真实发件域名并完成邮件服务商要求的SPF/DKIM等验证。
2. Auth Site URL使用`https://wuxufinance.github.io/wuxufinance/learn/`，Redirect URLs精确允许`https://wuxufinance.github.io/wuxufinance/learn/?auth=signup`与`https://wuxufinance.github.io/wuxufinance/learn/?auth=recovery`，避免宽泛通配。
3. 保持邮箱确认开启。注册确认和密码找回模板使用Supabase生成的`{{ .ConfirmationURL }}`，需要手工验证码入口时同时展示`{{ .Token }}`；不得自行拼接用户可伪造的登录token。
4. 配置合适的Auth发送/验证/登录限流。需要提高防滥用级别时，后续可接入Supabase支持的验证码；当前有提供商限流、表单冷却与蜜罐，未声称已部署CAPTCHA。
5. 使用所有者指定的测试邮箱，实际验收注册、收到邮件、点击验证、登录后返回原课程、退出、找回邮件和新密码登录；验证过期/错误验证码不会登录。另用第二设备验证账号进度合并。
6. 验收通过后，在管理后台“商品、订单与授权 → 访问与邮件配置”勾选“邮件配置与真实投递已经验收”。此开关只控制网站入口，不代替SMTP配置；关闭它不关闭已有账号登录。

Supabase Auth控制台的配置不由本仓库伪造。若提供商启用Secure Password Change等增强规则，需要按实际提供商流程补足并验收，不能只看前端成功提示。

## 管理员初始化

当前项目已有管理员，升级复用其身份，不重置密码，不把第一个注册用户设为管理员。

新环境中，项目所有者通过受控服务端配置创建唯一`zb_setup`记录：指定真实管理员邮箱、密码学随机的一次性令牌的SHA-256摘要；原始令牌仅私下交付本人，不能写入仓库、日志或公开页面。管理员在`learn/#setup=<一次性令牌>`完成原有首次开通流程，服务端核验摘要、指定邮箱及短期预留状态，成功后消费令牌并记录审计。不要重新开放已消费的生产开通记录。SMTP尚未可用时也不能以“首个注册用户”为替代。

普通用户通过修改metadata、URL、请求中的user_id/role、设备字段或数据库请求均不能提权。全部商品、价格、收款、退款和授权管理由后端管理员校验。

## 课程范围与未来内容

可逐讲配置`public_free`、`login_free`或`paid`，试听只公开明确选中的知识单元。正文、测试提交和工作簿下载共用后端课程权限判断。配套下载即使属于公开免费课程，也要登录并通过账号/设备检查。

商品和内部授权支持单讲、系列、课程包、全站。必须明确`include_future`；默认不包含未来新增课程。未包含未来时保存当时已发布讲次的快照；包含未来时按所选系列/全站自动覆盖新增已发布内容。单讲不支持包含未来课程。商品编辑不回写旧订单的名称、金额、币种、有效期或范围；新订单重新保存当时商品范围。

首次迁移没有把已有免费课程转为收费。新建商品不自动修改课程访问方式，修改为付费应先核查公开介绍、试听范围和商品映射。

## 订单、收款及退款

商品价格以后台最小货币单位整数保存，未定价只能保持草稿。购买页显示后台商品范围、是否包含未来课程和授权有效天数；没有定价时说明尚未配置。

待支付订单不产生权限。请求幂等键与每人每商品单个待支付订单约束避免重复下单，另有限制每小时创建数量。前端提供的价格、paid状态、截图或参数不作为支付依据。

当前仅允许管理员核实实际收款后填写唯一收款凭证编号及核实记录。事务原子写入收款事件、已支付订单与唯一购买授权。相同凭证重复提交不会重复开通；用于另一订单的同一收款凭证会被拒绝。未接入支付服务商，所有自动支付通知返回`PAYMENTS_NOT_CONFIGURED`。

订单状态包括待支付、已支付、已取消、已关闭、已退款。用户只能取消自己的待支付订单。管理员可关闭待支付订单；已支付订单仅在实际全额退款经核实后记录退款。后台按钮只记录事实，不执行真实付款或退款。退款撤销该订单的购买授权，不撤销其他购买或内部免费授权；当前不支持部分退款，接入前需另定规则。

## 内部免费授权

管理员按已注册邮箱查找用户，按单讲/系列/课程包/全站授予，可永久或指定到期。支持延期和撤销，保留来源、范围、有效期、操作人、时间和备注。免费授权不生成支付订单，不计入销售收入，也不会赋予后台权限。

有效权限采用“任意一项有效即可访问”：已开始、未过期、未撤销；购买来源还要求对应订单为已支付。内部授权和购买授权可同时存在。撤销、到期或退款仅影响对应来源。用户端显示已购/已授权及有效期，不返回内部备注和操作人字段。

## 数据、缓存与审计

应用表均启用RLS，撤销浏览器角色的表和RPC访问，只向service role授予应用所需权限。Edge先通过Supabase验证真实用户，再以数据库会话、设备和角色验证每个操作。公开接口固定匿名身份，不能通过参数获取私有正文或其他用户数据。

正文、下载、账户和权限接口使用`Cache-Control: no-store`，不让共享缓存保存受限响应。撤销后后端立即拒绝后续受限请求；客户端每45秒检查当前课程权限并刷新状态。已交付到授权浏览器或已下载的资料不能远程收回。

学习记录仅按已验证用户读写，保留原版本与并发合并机制。服务端评分防止导入伪造成绩；课程失去权限时保留旧学习记录，不删除用户仍有权访问的其他数据。

价格变更、访问配置、收款、退款和内部授权变更写入`zb_audit`；后台操作记录可展开查看。完整历史仍留在数据库，页面默认显示最近100条，不代表只保留100条。

## 发布、验证与回滚

1. `npm ci && npm run build && npm test`。
2. 使用完整当前私有课程导出运行`npm run audit:courses -- <私有导出路径>`，导出文件留在仓库之外。
3. 隔离Postgres执行游客、普通、购买、内部、管理员五类场景；验证过期、撤销、交叠来源、退款、重复收款、范围快照、RLS、会话撤销和进度并发。模拟订单和测试邮箱只存在于隔离环境。
4. 增量迁移先保存在`zb_release_snapshots`中的旧课程与旧函数，再添加表和替换命令；不修改43讲载荷和课程版本。发布后对比载荷摘要、学习记录和账号角色，避免覆盖并发修改。
5. 部署Edge代码并检查公开目录、受限正文、下载接口、未配置支付通知的线上状态。通过后发布main及gh-pages，确认Actions/Pages部署成功。
6. 必要时先回滚网页和Edge到升级前版本，再由所有者审核私有快照恢复旧`zb_command`。新增数据表可保留；不要直接删除订单、授权、审计或真实新增学习数据。

真实邮件与真实收款只有分别完成外部配置并验收后才可声明上线。本轮只交付无在线付款的权限与订单系统。


## 当前托管平台的公开正文限制

Supabase默认项目域名会把HTML/XHTML页面响应改为纯文本，不能作为网页HTML托管。因此公开介绍保持GitHub Pages原有完整静态HTML、标题、目录及canonical，公开全文或试听通过匿名内容接口在该页增强显示；旧API阅读地址会跳转到对应正式介绍页，不再让用户看到源码。

这一限制不影响现有43讲的登录学习及64个静态搜索页面。未来如果将课程完整正文改为公开、并要求正文无需JavaScript就能被抓取，需要先配置可返回HTML的正式后端域名/托管，再接入服务端页面；本轮没有自行购买域名、付费升级或声称已完成这种全文收录。
